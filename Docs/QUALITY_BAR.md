# QUALITY_BAR.md

# ArmyRush Quality Bar

Version: 1.0
Status: Mandatory

---

# Purpose

This document defines the minimum acceptable quality level for ArmyRush.

Anything below this quality bar is incomplete.

---

# Golden Rule

Working is not enough.

Finished is not enough.

Polished is required.

---

# Production Standard

ArmyRush should feel comparable to:

Top mobile runner games

Top crowd battle games

Top hyper-casual productions

Commercial App Store releases

---

# Feature Completion Requirements

Every feature must satisfy:

Functionality

Visual Quality

Audio Quality

Performance

Documentation

Testing

---

# Gameplay Quality

Gameplay must be:

Responsive

Readable

Fair

Rewarding

Addictive

---

# Input Quality

Controls must feel:

Immediate

Smooth

Reliable

Predictable

---

# Visual Quality

No placeholder art.

No default materials.

No prototype assets.

No grayboxing in production.

---

# Animation Quality

Every major interaction requires animation.

No static experiences.

---

# Audio Quality

Every major action requires audio feedback.

No silent interactions.

---

# VFX Quality

Every major action requires visual feedback.

No invisible rewards.

---

# UI Quality

No default Unity buttons.

No debug UI.

No unfinished layouts.

No clipped content.

---

# Performance Quality

Target:

60 FPS

Required:

Stable gameplay

No major frame drops

---

# Memory Quality

Avoid unnecessary allocations.

Pool reusable objects.

---

# Error Quality

Required:

0 compiler errors

0 console errors

0 missing references

0 broken prefabs

---

# Level Quality

Every level must:

Contain decisions

Contain progression

Contain rewards

Contain pacing

Contain feedback

---

# Progression Quality

Players must feel stronger.

Every few runs should unlock meaningful progress.

---

# Boss Quality

Bosses must feel unique.

Bosses must feel memorable.

Bosses must feel rewarding.

---

# Mobile Quality

Must function correctly on:

iPhone

iPad

Different resolutions

Safe areas

---

# Release Candidate Checklist

Before release:

No placeholder content

No broken systems

No console errors

No missing references

No unfinished UI

No unfinished audio

No unfinished VFX

Stable performance

Documentation updated

---

# Done Checklist

A task is DONE only if:

Works correctly

Looks polished

Sounds polished

Performs correctly

Documented correctly

Tested correctly

---

# Not Done Examples

Works but ugly

Works but no audio

Works but no VFX

Works but no documentation

Works but has errors

Works but unoptimized

These are NOT complete.

---

# Codex Instructions

Do not lower the quality bar.

Do not mark incomplete work complete.

Do not prioritize speed over quality.

Do not leave temporary solutions in production.

Every completed system must satisfy this document.

This document defines what "done" means.
